二、前置知识

2.1 PHP 是 C 语言写的

PHP 解释器（Zend Engine）是用 C 语言开发的。这意味着 PHP 内部有：

  • 指针、内存地址
  • malloc/free 手动内存管理
  • C 语言的各类潜在漏洞（包括 UAF）

2.2 disable_functions 是在哪一层实现的？

关键：disable_functions 只是在函数表条目上打了一个”禁用”标记（is_disabled = true），并没有把 system() 的 C 代码从内存中删除。

3.3 UAF 是 PHP 特有的吗？

不是！ UAF 是 C/C++ 世界的通用内存漏洞：

软件 语言 著名的 UAF 漏洞
PHP 7.x C 本脚本利用的 UAF
Chrome V8 C++ 无数 UAF
Linux 内核 C CVE-2021-0920
Adobe Reader C++ CVE-2018-8653

因为它们都是 C/C++ 写的，都需要手动管理内存。

七、总结

概念 说明
UAF Use-After-Free，释放后使用，C/C++ 内存漏洞
关键点 disable_functions 只是标记，函数代码还在内存里
绕过原理 篡改闭包的 handler 指向 system()，跳过 is_disabled 检查
为什么能绕过 PHP 信任闭包，闭包的调用路径不检查 is_disabled
前提 需要目标 PHP 版本存在 UAF 漏洞（本脚本适用于 PHP 7.x）
